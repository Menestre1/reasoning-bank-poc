# 📚 Полное руководство по инструментам системы Лирь

Этот навык содержит описание всех доступных инструментов (slash-команд) в системе Лирь. Используйте его, чтобы понять, какие инструменты доступны и когда их применять.

---

## 🎯 Когда использовать инструменты vs обычный чат

### Используйте **инструменты** (slash-commands), когда:
- Нужно загрузить данные с диска (конфигурации, измерения)
- Требуется поиск по коду или семантический поиск
- Нужно построить графы или найти зависимости
- Требуется сравнение конфигураций
- Нужно извлечь код из файлов

### Используйте **обычный чат**, когда:
- Нужны объяснения концепций 1С
- Требуется помощь в написании кода
- Нужно обсудить архитектуру или паттерны
- Вопросы общего характера

## 📋 Список всех инструментов

### 1. `/load-config <путь>`
**Назначение**: Загрузка и анализ конфигурации 1С из директории

**Когда использовать**:
- Пользователь просит проанализировать конфигурацию 1С
- Нужно загрузить код модулей для дальнейшего поиска
- Фраза-триггер: "проанализируй конфигурацию", "загрузи конфигурацию"

**Параметры**:
- `targetPath` (string) — путь к директории с конфигурацией

**Пример**:
```
/load-config C:\my-config
```

---

### 2. `/search-code <запрос>`
**Назначение**: Полнотекстовый поиск по загруженному коду (FTS5 с русской морфологией)

**Когда использовать**:
- Нужно найти вхождения определенного текста в коде
- Поиск по конкретному методу или переменной
- Фраза-триггер: "найди в коде", "поищи по коду"

**Параметры**:
- `query` (string) — текст для поиска

**Пример**:
```
/search-code ТестоваяПроцедура
```

---

### 3. `/semantic-search <запрос>`
**Назначение**: Семантический поиск в базе памяти (векторный поиск)

**Когда использовать**:
- Нужен поиск по смыслу, а не по точному совпадению
- Поиск похожих решений из прошлого опыта
- Фраза-триггер: "найди похожее", "искал ли я раньше"

**Параметры**:
- `query` (string) — описание для семантического поиска

**Пример**:
```
/semantic-search как оптимизировать запрос к базе данных
```

---

### 4. `/load-measurements <путь>`
**Назначение**: Загрузка данных о производительности из JSON-файлов

**Когда использовать**:
- Нужно проанализировать производительность объектов
- Есть файлы с результатами замеров
- Фраза-триггер: "загрузи замеры", "загрузи измерения"

**Параметры**:
- `dirPath` (string) — путь к папке с JSON-файлами замеров

**Пример**:
```
/load-measurements C:\measurements
```

---

### 5. `/top-slow [лимит] [объект]`
**Назначение**: Показать топ N самых медленных объектов

**Когда использовать**:
- Нужно найти узкие места в производительности
- Анализ тормозящих объектов
- Фраза-триггер: "самые медленные", "топ медленных"

**Параметры**:
- `limit` (number, опционально, по умолчанию 10) — количество объектов
- `objectName` (string, опционально) — фильтр по конкретному объекту

**Пример**:
```
/top-slow 20
/top-slow 10 МояФорма
```

---

### 6. `/explain-slow <объект>`
**Назначение**: Статистика и анализ медленного объекта

**Когда использовать**:
- Нужно понять, почему объект работает медленно
- Детальный анализ производительности конкретного объекта
- Фраза-триггер: "почему медленно", "объясни тормоза"

**Параметры**:
- `objectName` (string) — имя объекта для анализа

**Пример**:
```
/explain-slow МояФорма
```

---

### 7. `/build-graph`
**Назначение**: Построение графа зависимостей из загруженной конфигурации

**Когда использовать**:
- Нужно визуализировать связи между модулями
- Анализ архитектуры конфигурации
- Фраза-триггер: "построй граф", "покажи зависимости"

**Параметры**: Нет

**Пример**:
```
/build-graph
```

---

### 8. `/callers <Объект.Метод>`
**Назначение**: Найти все методы, которые вызывают указанный объект или метод

**Когда использовать**:
- Нужно понять, кто использует данный метод
- Анализ влияния изменений
- Фраза-триггер: "кто вызывает", "поиск вызовов"

**Параметры**:
- `objectName` (string) — имя объекта
- `methodName` (string, опционально) — имя метода в формате `Объект.Метод`

**Пример**:
```
/callers МойОбъект.МойМетод
/callers МойОбъект
```

---

### 9. `/callees <Объект.Метод>`
**Назначение**: Найти все методы, которые вызываются из указанного объекта или метода

**Когда использовать**:
- Нужно понять, что использует данный метод
- Анализ зависимостей метода
- Фраза-триггер: "что вызывает", "какие методы использует"

**Параметры**:
- `objectName` (string) — имя объекта
- `methodName` (string, опционально) — имя метода в формате `Объект.Метод`

**Пример**:
```
/callees МойОбъект.МойМетод
```

---

### 10. `/cycles`
**Назначение**: Поиск циклических зависимостей в графе

**Когда использовать**:
- Нужно найти циклы в зависимостях
- Проверка архитектуры на циклические ссылки
- Фраза-триггер: "найди циклы", "циклические зависимости"

**Параметры**: Нет

**Пример**:
```
/cycles
```

---

### 11. `/graph-viz [объект]`
**Назначение**: Экспорт графа зависимостей в формат GraphML для визуализации

**Когда использовать**:
- Нужно открыть граф в yEd или Gephi
- Экспорт графа для презентации
- Фраза-триггер: "экспорт графа", "визуализация графа"

**Параметры**:
- `objectName` (string, опционально) — экспорт графа только для конкретного объекта

**Пример**:
```
/graph-viz
/graph-viz МойОбъект
```

---

### 12. `/compare-config <старая> <новая>`
**Назначение**: Сравнение двух конфигураций и обнаружение изменений

**Когда использовать**:
- Нужно сравнить две версии конфигурации
- Поиск изменений между релизами
- Фраза-триггер: "сравни конфигурации", "что изменилось"

**Параметры**:
- `oldPath` (string) — путь к старой конфигурации
- `newPath` (string) — путь к новой конфигурации

**Пример**:
```
/compare-config C:\config-old C:\config-new
```

---

### 13. `/comparison-summary`
**Назначение**: Показать сводку последнего сравнения конфигураций

**Когда использовать**:
- Нужна краткая сводка по изменениям
- Просмотр статистики сравнения
- Фраза-триггер: "сводка сравнения", "итоги сравнения"

**Параметры**: Нет

**Пример**:
```
/comparison-summary
```

---

### 14. `/diff-module <объект>`
**Назначение**: Показать различия между версиями модуля из сравнения

**Когда использовать**:
- Нужно увидеть, что конкретно изменилось в модуле
- Детальный diff изменений
- Фраза-триггер: "покажи diff", "что изменилось в модуле"

**Параметры**:
- `objectName` (string) — имя объекта/модуля

**Пример**:
```
/diff-module МойОбъект
```

---

### 15. `/changed-objects [тип]`
**Назначение**: Список объектов, измененных при последнем сравнении

**Когда использовать**:
- Нужен список всех измененных объектов
- Фильтрация по типу объектов
- Фраза-триггер: "измененные объекты", "что изменилось"

**Параметры**:
- `type` (string, опционально) — фильтр по типу объекта

**Пример**:
```
/changed-objects
/changed-objects Форма
```

---

### 16. `/explain <Объект.Метод>`
**Назначение**: Объяснение работы метода с помощью LLM-анализа

**Когда использовать**:
- Нужно понять, как работает конкретный метод
- LLM-анализ кода метода
- Фраза-триггер: "объясни метод", "как работает"

**Параметры**:
- `fullName` (string) — имя объекта и метода в формате `Объект.Метод`

**Пример**:
```
/explain МойОбъект.МойМетод
```

---

### 17. `/extract-my-code <входной> [выходной]`
**Назначение**: Извлечение процедур/функций из файла модуля 1С с маркерами (AVS, Kosmachev)

**Когда использовать**:
- Нужно выделить код из текстового файла
- Извлечение процедур по маркерам комментариев
- Фраза-триггер: "извлеки код", "выдели процедуры", "extract my code"

**Параметры**:
- `inputFile` (string) — путь к входному файлу
- `outputFile` (string, опционально, по умолчанию `./extracted_code.txt`) — путь к выходному файлу

**Пример**:
```
/extract-my-code C:\my-code.txt
/extract-my-code C:\input.txt C:\output.txt
```

**Поддерживаемые маркеры**:
- `// AVS` или `# AVS` — маркер AVS
- `// Kosmachev` или `# Kosmachev` — маркер Kosmachev

## 💡 Советы по использованию

1. **Начинайте с загрузки данных**: `/load-config` или `/load-measurements`
2. **Используйте поиск**: `/search-code` для точного поиска, `/semantic-search` для поиска по смыслу
3. **Анализируйте зависимости**: `/build-graph`, `/callers`, `/callees`
4. **Сравнивайте конфигурации**: `/compare-config`, `/diff-module`
5. **Не забывайте про отзывы**: после ответа агента отвечайте "да" или "нет" для обучения

- `/models` — список доступных моделей
- `/lang` — выбрать язык программирования
- `/exit` или Ctrl+C — выход
