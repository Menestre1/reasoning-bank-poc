# Диагностика проблем проведения документа при утере регистров

Если документ не проводится из-за отсутствия регистров (например, после сокращения базы):

## 🔍 Шаги диагностики

1. **Включите технологический журнал** с событиями `EXCP`, `DBMSQL`, `TLOCK`.
2. **Найдите точное исключение** – в журнале будет сообщение об ошибке с указанием отсутствующего регистра или таблицы.
3. **Проверьте состав регистров** в конфигурации: сравните с эталонной базой (если есть).
4. **Используйте `/search-code`** для поиска упоминаний проблемного регистра в модулях документа.
5. **Проверьте метаданные** через `/load-config` и поищите, какие регистры использует документ.
6. **Восстановите недостающие регистры** из рабочей базы или добавьте вручную.

## 📂 Полезные команды для диагностики

- `/load-config <путь>` — загрузить конфигурацию для анализа
- `/search-code <запрос>` — найти где используется проблемный регистр
- `/explain <Объект.Метод>` — понять логику проведения
- `/compare-config <старая> <новая>` — сравнить конфигурации и найти удаленные регистры

## 💡 Возможные причины

- **Сокращение базы**: при удалении старых регистров не учли зависимости
- **Обмен данными**: причина в настройках правил обмена – проверьте правила для данного документа
- **Нехватка прав**: пользователь не имеет доступа к нужным регистрам
- **Конфликт блокировок**: регистр заблокирован другим соединением

## 🛠️ Что делать

1. Определите, каких именно регистров не хватает (по тексту ошибки)
2. Найдите их в рабочей базе или эталонной конфигурации
3. Создайте недостающие регистры в текущей базе
4. Проверьте код проведения: нет ли обращения к несуществующим регистрам
5. Если проблема в обмене — настройте правила обмена для переноса данных регистров
